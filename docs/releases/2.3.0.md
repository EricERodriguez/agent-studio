# Agent Studio 2.3.0

Fecha de release: 2026-08-15

## Alcance

Esta versión termina la mejora del workflow graph como superficie de trabajo
accesible, adaptable y observable. Cubre tanto la interacción del editor como
la ejecución visible de Claude/Codex y el feedback de una corrida real.

## Cambios incluidos

### Grafo accesible y adaptable

- El canvas usa Pointer Events con captura, paneo limitado y cancelación segura.
- Nodos, enlaces, zoom, `Fit graph` y minimapa tienen rutas de teclado, nombres
  accesibles y foco visible.
- El rail se redimensiona y conserva el ancho. Agent Rail, Workflow toolbar,
  Minimap y Run status se contraen/restauran de forma independiente y persisten
  su estado.
- Un Run status contraído conserva la acción compacta para detener una corrida
  activa.

### Ejecución de Codex visible

- `cli-codex` usa el runner de terminal interactiva, igual que Claude, y abre
  una terminal integrada de VS Code por nodo; los nodos paralelos se dividen con
  el split nativo de terminales.
- El runner espera Shell Integration y entrega el turno inicial a Codex como
  argumento posicional seguro. Esto evita el fallo donde Codex se cerraba y el
  prompt quedaba pegado en una shell vacía.
- El criterio de aceptación exige observar la TUI real de Codex, el título de
  terminal de Agent Studio y los estados del workflow; una ejecución headless
  no es válida.

### Movimiento semántico del workflow

- El graph agrega entradas escalonadas, profundidad sutil de canvas, feedback
  de pan/zoom, spinner de carga, transiciones de estado, hover y arrastre.
- Nodos, minimapa y Run status comunican los estados `queued`, `running`,
  `waiting_approval`, `completed`, `failed` y `skipped` de manera consistente.
- El viajero de una arista sólo aparece durante un handoff verdadero:
  `completed → running`. Mientras el nodo origen trabaja, la arista queda activa
  pero sin sugerir que el trabajo ya fue entregado.
- `prefers-reduced-motion` detiene entradas, pulsos, viajeros y el spinner de
  carga.

## QA de aceptación en VS Code

La validación no se realizó en un navegador externo. Se inició un Extension
Development Host aislado con perfil y extensiones temporales, se abrió el
dashboard mediante Command Palette y se ejecutó el workflow de dos pasos
`Refinamiento visual de HTML y estilos` con Codex CLI.

| Instante observado | Resultado |
| --- | --- |
| Primer agente activo | `visual-ui-auditor` estaba `running`; el nodo tenía estado de carga y la arista era `graph-edge-running`, sin viajero. |
| Handoff real | Al completarse el primer agente, `visual-ui-refiner` pasó a `running`; la arista pasó a `graph-edge-handoff-flow` y apareció un único viajero. |
| Terminales | El panel inferior de VS Code mostró las terminales Codex de los agentes, incluida la TUI y sus títulos de Agent Studio. |
| Movimiento reducido | Se inspeccionó la hoja de estilo cargada por el webview: la regla de `prefers-reduced-motion` incluye `graph-node-loading`. |

Las instrucciones reproducibles para futuras IA están en el
[protocolo de QA dentro de VS Code](../swarmforge-integration/09-protocolo-qa-ia-vscode.md)
y su [checklist EDH](../swarmforge-integration/08-checklist-edh.md).

## Empaquetado

El artefacto de esta versión es `agent-studio-ia-2.3.0.vsix`. Se genera desde
la raíz con:

```sh
npm run package:vsix
```

El comando construye extensión y webview antes de invocar `@vscode/vsce` y
debe ejecutarse con `package.json` ya versionado en `2.3.0`.

El paquete excluye `.agent-studio/runs/`: esos manifests, objetivos y salidas
son artefactos locales de ejecución/QA y no forman parte de una distribución.
